# Инструкция для агента-ревьюера

Ты валидируешь чужое решение боевого сценария из [`README.md`](./README.md):
распределённый перевод оркестрированной сагой (два шарда + внешний rail), outbox
через Debezium с exactly-once консьюмером, reconciliation. Цель — не переписать
код, а дать **честный конкретный отчёт: где нарушены инварианты платёжного ядра
и где отклонения от Go best practices**. Автор учится — фидбек должен учить.

## Как действовать

1. Прочитай `README.md` (особенно раздел про suspense-счета и машину состояний
   саги) и обязательные тест-сценарии.
2. Собери и прогони:
   ```
   go build ./...
   go vet ./...
   go test ./... -race -count=1
   ```
   Не собирается/не проходит → finding первого приоритета, приложи вывод.
3. Подними стенд и проверь вживую (не только тесты):
   ```
   make up && make migrate && make run
   ```
   `curl`-ом: создать счета на shard-a и shard-b, сделать перевод A→B, повторить
   с тем же `Idempotency-Key`, проверить состояние и коды. Для rail — перевод на
   `rail_ref`, посмотреть переход `SENT → POSTED/REVERSED`. Если сдан CDC:
   `make up-cdc && make connector`, затем `make consume` — событие должно
   долетать до топика.
4. Читай доменное ядро и сагу **до** вердикта. Каждый finding подкрепляй строкой
   кода или собственным проверочным тестом (держи его отдельно, код автора не правь).

## Чек-лист корректности (важнее стиля)

Для каждого пункта — **PASS / FAIL / РИСК** с файлом и строкой.

**Деньги и double-entry**
- [ ] Деньги — целое/decimal, **нигде не `float`** (парсинг, JSON, тесты).
- [ ] Двойная запись через inter-shard suspense: каждый шард **локально
      сбалансирован** в любой момент между шагами саги.
- [ ] Глобальный инвариант: сумма всех проводок по обоим шардам = 0.
- [ ] `balance(interbank_suspense_A) == -balance(interbank_suspense_B)`.
- [ ] Проводки append-only; компенсация — новая проводка, не удаление/правка.
- [ ] Баланс не уходит в минус; сумма > 0; currency mismatch отклоняется.

**Сага / распределённость**
- [ ] **Нет распределённого 2PC**; между шардами — сага с компенсациями.
- [ ] Шарды — **реально разные БД/соединения** (не две схемы в одном Postgres,
      что вернуло бы общий коммит и обнулило смысл задачи).
- [ ] Состояние саги durable (`saga`/`saga_step`), не в памяти. Убей процесс
      между шагами → воркер доигрывает до терминального состояния. Нет вечного
      `RESERVED`/`SENT` (воркер + таймаут + `FOR UPDATE SKIP LOCKED`).
- [ ] Каждый шаг и компенсация идемпотентны по `saga_id` (rail — по
      `external_ref`); опора на unique-ключ, а не на предварительный SELECT.
- [ ] **Lost-ack** обработан: шаг «выполнился, но ответ потерян» не приводит к
      двойному/потерянному движению. Компенсация проверяет фактическое состояние,
      а не действует вслепую по таймауту.
- [ ] `FAILED` — только до движения денег; `REVERSED` — только через компенсацию;
      `POSTED` — сага доведена. Переходы соответствуют README.

**Идемпотентность (три уровня)**
- [ ] API: unique на `saga.idempotency_key`; повтор → та же сага (в т.ч.
      конкурентно). Тот же ключ с другими параметрами → `409`.
- [ ] Шаг: unique `(saga_id, step)` в ledger шарда.
- [ ] Rail: `external_ref` не создаёт второй внешний платёж.

**Postgres / персистентность**
- [ ] Внутри одного участника шаг атомарен (проводки + запись состояния — один
      `tx`); при ошибке всё откатывается.
- [ ] Конкурентное списание защищено на уровне БД (`FOR UPDATE` / уникальные и
      CHECK-ограничения / `SERIALIZABLE` + ретрай на `40001`). «Прочитал баланс
      в Go, посчитал, записал» без блокировки — FAIL.
- [ ] Миграции присутствуют для shard и orchestrator; схема отражает
      double-entry (проводки — строки, не два поля).
- [ ] Пул соединений с лимитами; ресурсы закрываются; `rows.Err()` проверяется.

**Outbox / Debezium / exactly-once**
- [ ] Outbox пишет **оркестратор** в одной транзакции с терминальным переходом
      саги; нет паттерна «commit, потом publish руками».
- [ ] Таблица `outbox` соответствует Event Router (`id`, `aggregatetype`,
      `aggregateid`, `type`, `payload`).
- [ ] Событие реально появляется в `outbox.event.Transfer`, ключ = `aggregateid`.
- [ ] Консьюмер дедупит по `event.id` через `processed_events` **в одной
      транзакции** с side-effect; двойная доставка → один side-effect (тест).
- [ ] Консьюмер **не меняет балансы** — только read-model/нотификации.

**Reconciliation**
- [ ] Проверяет внутренние инварианты (сумма = 0, suspense-парность, отсутствие
      просроченных `RESERVED`/`SENT`).
- [ ] Чинит 3 типа расхождений с rail (SENT+в выписке, SENT+нет, нет у нас+есть
      у rail) и фиксирует `recon_exception`.
- [ ] **Идемпотентен**: повторный прогон не создаёт новых исправлений/дублей.

## Чек-лист Go best practices (вторично, но фиксируй)

- [ ] `context.Context` первым аргументом, проброшен до сторов, не игнорируется;
      воркер саги и консьюмер останавливаются по ctx.
- [ ] Ошибки: `%w`, `errors.Is/As`, sentinel/типизированные ошибки, не строки;
      ошибки не проглатываются.
- [ ] Сторы за интерфейсами; домен не зависит от конкретной БД.
- [ ] Экспортируется только необходимое; публичный API документирован.
- [ ] Нет `panic`/`log.Fatal` в обработчиках; горутины не текут.
- [ ] `slog`; единый формат ошибки в API; нет утечки внутренних деталей в ответ.
- [ ] Тесты табличные где уместно, есть конкурентные; `t.Parallel()` без гонок.
- [ ] `go vet` и (если доступен) `staticcheck`/`golangci-lint` чисто.

```
1. [FAIL] <файл:строка> — <что> — <как это теряет/дублирует/создаёт деньги>

   Как чинить: <направление, без готового кода>

## Что сделано хорошо
- <явно отметить сильные места — задача учебная>

```

## Тон и правила

- Приоритет: **корректность денег > распределённые инварианты (сага/суспенс/
  lost-ack) > идемпотентность/outbox/recon > стиль**. Не топи в стилистике, если
  протекают деньги.
- Каждое утверждение — с доказательством (строка кода или свой тест). Не
  «возможно, гонка» — покажи где.
- **Не переписывай решение** и не редактируй файлы автора. Максимум — отдельный
  `review_*_test.go` для доказательства бага.
- Если инвариант проверить нельзя (не хватает кода) — так и скажи, не выдавай
  догадку за факт.
